# Annotated Hex Dump

The project requires an annotated complete request/response dump. The exact bytes below are deterministic for the example values and are also a guide for the `-v` output generated by `bcurl`.

## Request

Logical request:

```text
GET-like operation
path: /index.html
Host: localhost
User-Agent: cn-bcurl/1
```

Wire layout:

```text
43 4e | 01 | 01 | 00 | 00 | 00 02 | 00 00 00 25 | 00 00 00 01 
^^^^^   ^^   ^^   ^^   ^^   ^^^^^^^   ^^^^^^^^^^^   ^^^^^^^^^^^
magic   ver type flags reserved headers payload_len stream_id
```

The header count is `2` because the request contains `Host` and `User-Agent`.

The payload then contains:

```text
00 0b                         path length = 11
2f 69 6e 64 65 78 2e 68 74 6d 6c   "/index.html"
08                            header ID 8 = Host
00 09                         value length = 9
6c 6f 63 61 6c 68 6f 73 74    "localhost"
09                            header ID 9 = User-Agent
00 0a                         value length = 10
63 6e 2d 62 63 75 72 6c 2f 31  "cn-bcurl/1"
```

## Response

Logical response:

```text
status: 200
Content-Type: text/html; charset=utf-8
Content-Length: ...
Server: cn-observe/1
Connection: keep-alive
body: file bytes
```

The `-v` output from the real run is the authoritative final artifact because the body length depends on the file you serve.

Run:

```bash
./build/observe ./www 9000
./build/bcurl -v localhost:9000/index.html
```

Then copy the request and response blocks into this document and annotate each field using `PROTOCOL.md`.

## Why this matters

The course requirement is not merely “make curl-like output.” The point is to be able to look at raw bytes and explain:

```text
these 2 bytes → magic
this byte      → version
this byte      → frame type
these 4 bytes  → payload length
these bytes    → path
these bytes    → headers
remaining      → body
```

If we cannot do that, the protocol is not yet understood.
